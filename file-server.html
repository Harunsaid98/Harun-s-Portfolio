How the file server was set up

The lab runs on the same lab.local domain. I used a dedicated Windows Server 2025 member server, FS01, with a separate data disk for Finance and HR shares. Domain clients were used for access tests.

Work completed

Six support tickets

2001

Finance permissions

Created Modify and Read-only roles. Confirmed Finance users could edit, reviewers could read, and unrelated accounts were denied. An early failure came from an incorrectly typed network path.

2002

HR share

Set up a separate HR share and tested access using HR and Finance accounts. The direct HR path refused the Finance user as intended.

2003

Automatic drive mapping

Mapped Finance to F: and HR to H: through Group Policy Preferences. I corrected an AND condition to OR so either authorized Finance group could receive the drive.

2004

Department transfer

Moved a test account from Finance to HR, changed group membership, then verified that the correct drive and share access appeared after a fresh sign-in.

2005

Deleted file recovery

Backed up the Finance share, deleted Budget-2026.txt, and restored just that file. I verified its content and original access-control entries after recovery.

2006

Access denied after joining a group

A user's membership was updated, but access remained denied until the old Windows logon token was replaced by a new sign-in.

Troubleshooting example

Why was Finance still denying access?

Problem

The test user had been added to GG_Finance_Users, but the Finance share still returned Access denied.

Cause

The current sign-in session held an old security token that did not include the user's new group membership.

Verification

After a full sign-out and sign-in, whoami /groups showed the Finance groups and the share opened. I did not change the file-server permissions to resolve it.

What I took from this

Check the whole access path

When a mapped drive or shared folder fails, the cause might be the UNC path, DNS, network connectivity, group membership, SMB permissions, NTFS permissions, Group Policy targeting, or the current logon token. This lab helped me separate those layers instead of changing permissions at random.

Scope and limitations

This is a personal lab, not a production file server. The one-time recovery backup was stored on the same FS01 VM, so it demonstrates restoration but does not provide off-site protection or a backup schedule.
